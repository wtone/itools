# iTools 访达右键菜单

## 0.6.0：系统能力优先，减少重复步骤

本轮检查全部 47 个动作。能调用公开系统接口或明确交给其他应用的直接联动；没有相应公开接口时，用直接文件操作或单次参数窗口补足。不使用模拟键盘、菜单坐标点击或私有 Finder API，因此不会为此新增辅助功能、自动化授权步骤。

| 动作 | 处理方式与必要交互 |
| --- | --- |
| TXT、Markdown、RTF、JSON、HTML、CSV、XML（7 项） | Finder 没有直接新建这些文档的公开命令；在目标目录直接创建并用系统 API 选中，重名编号 |
| 自定义模板新建 | 单个已存模板直接使用；多个模板选择一次；无模板时用系统文件选择器选原始文档 |
| 移动、复制、移动至同步文件夹（3 项） | 系统目录选择器取得目标，直接执行不覆盖的文件操作；同步由目标目录所属客户端完成 |
| 剪切、粘贴移动（2 项） | 使用系统标准文件 URL 剪贴板，接受 Finder 拷贝的文件；文件移动完成后只移除本次成功项，新复制的内容不被覆盖 |
| 拷贝名称、拷贝路径（2 项） | 直接写入系统文本剪贴板 |
| 使用文件名新建文件夹 | 直接创建并在 Finder 选中，不再询问「新建？」 |
| 解散文件夹 | 冲突预检后直接上移内容、移除空目录；仍有内容的目录不递归删除，失败时报告 |
| 添加到常用目录、打开常用目录（2 项） | iTools 自身的常用目录列表；不是 Finder 侧边栏。单个目录直接通过 Finder 打开，多个目录只选一次 |
| 重命名 | 无可靠的公开 Finder 重命名编辑器入口；单个文件直接输入名称，多文件在同一窗口编辑前缀 / 编号、查看预览并应用 |
| 设置图标、恢复默认图标（2 项） | 系统选图后 NSWorkspace.setIcon，恢复直接 setIcon(nil)，不再确认一次 |
| 发送快捷方式到桌面 | 创建标准 Finder alias 文件并用 Finder 选中，不创建自有快捷方式格式 |
| 隔空投送 | NSSharingService.sendViaAirDrop，接收者由系统界面选择，不增加 iTools 发送确认 |
| 进入终端 | NSWorkspace 将准确目录交给 Terminal，不拼接脚本 |
| 打开方式 | Finder 子菜单直接显示 Launch Services 返回的应用，多选取共同支持项；选中即打开。「其他应用」才显示系统应用选择器 |
| 取消隐藏、隐藏、扩展名（3 项） | 直接修改 Finder 使用的文件元数据；点号文件名 / 全局扩展名设置仍遵循 Finder 规则 |
| 修复乱码文件名 | 编码选择、候选名称预览、应用在同一窗口；不再先选编码再开确认窗口 |
| 授予写入权限 | 直接增加当前用户所拥有项目的 owner-write，保留其他权限位，不递归、不提权 |
| 扫描、SHA-256（2 项） | 系统无对应现成右键流程，使用后台计算及独立结果窗口；扫描可取消 |
| 移到废纸篓 | NSWorkspace.recycle，系统自己决定是否显示进度或异常界面，iTools 不额外确认 |
| 彻底删除 | 一个窗口展示项目、说明无法从废纸篓恢复并输入确认；保留根目录 / 主目录保护 |
| 快速 7z、快速 ZIP、普通 ZIP（3 项） | 没有公开 Finder 压缩调用接口，使用已内置的压缩引擎直接生成、校验并选中结果 |
| 快速 7z / ZIP / 普通 ZIP 并移到废纸篓（3 项） | 菜单名称已明确动作；压缩校验及原件快照检查通过后调用系统废纸篓，不再弹两轮确认；失败保留原件 |
| 加密 7z、加密 ZIP（2 项） | 无内存密码时输入一次，随后直接压缩；不额外选择预设保存位置 |
| 自定义压缩 | 保留选项和系统保存位置选择，因为这两项尚未从菜单确定 |
| 设置加密密码 | 一个密码窗口完成设置 / 替换 / 清除，取消后无额外消息 |
| 校验压缩包 | 先直接检查；只有实际密码错误 / 需要密码时才询问。普通损坏或读取失败报错，不误当作需要输入空密码 |
| 用 FastZip 打开 | 直接将所选文件交给已安装 FastZip；未公开的专有操作不猜测 URL 或模拟点击 |

文件剪贴板现在与 Finder 及其他应用共享，生命周期由系统管理；后台组件闲置退出不会清空系统剪贴板。密码仍只保存在组件内存中。成功后若 Finder 或目标应用已展示结果，不再弹成功确认。

另已检查本机 FastZip 3.0.7 / iRightMouse 2.4.9 的 Info.plist：它们注册了各自 URL scheme，但没有 AppleScript 字典。在本轮查阅的[FastZip 官方说明](https://www.better365.cn/fastzip.html)与[iRightMouse 官方说明](https://better365.cn/irightmouse.html)中未找到可依赖的动作参数协议，所以不把「注册了 scheme」当作能直接调用任意压缩 / 右键命令的依据；标准文件打开可直接交接，其他能力采用上表的实现。原应用自己的 Finder 菜单继续保留。

系统接口依据：[NSWorkspace.recycle](https://developer.apple.com/documentation/appkit/nsworkspace/recycle(_:completionhandler:))；本机 macOS SDK 14.2 的 NSWorkspace.h（urlsForApplications(toOpen:) 从 macOS 12 可用）；[Apple 的 Finder 文件拷贝 / ⌥⌘V 移动快捷键](https://support.apple.com/en-us/102650)。

## 0.5.0 历史实现：从 Finder 直接执行

Finder 菜单直接交给随应用打包的后台操作组件，主程序保持原状；未运行时也不会拉起主窗口。普通操作不再经过「访达与文件 → 确认并执行」。

| 操作 | 点击后的行为 |
| --- | --- |
| 新建 TXT / Markdown / RTF / JSON / HTML / CSV / XML | 在右键目标目录生成未命名文件、重名自动编号并在 Finder 中选中，按回车即可重命名 |
| 进入终端 | 选中文件夹则打开该目录，选中文件则打开其父目录；路径直接交给系统 API，不拼接 shell 命令 |
| 复制路径 / 名称、隐藏 / 显示、切换扩展名、恢复图标、添加常用目录、创建同名文件夹 | 直接处理所选项目；失败时显示原因 |
| 剪切 / 粘贴移动 | 剪切记录在后台组件的当前会话，粘贴直接移动到右键目录；不覆盖重名文件 |
| 移动 / 复制 / 同步目录 | 仅选择目标目录后执行，不再跳转主窗口 |
| 快速打包 / 普通 ZIP | 直接保存到所选项目旁边，重名自动编号，完成后在 Finder 中选中压缩包 |
| 加密 / 自定义压缩、模板、图标、打开方式 | 仅显示所需参数或文件选择器 |
| 重命名、解散、权限变更、删除及压缩后移除原件 | 直接进入对应预览 / 确认对话框，继续保留原有冲突校验及删除保护 |
| 扫描 / SHA-256 / 压缩校验 | 耗时操作显示独立进度窗，结果可查看与复制；扫描可停止 |

后台组件不启动剪贴板记录、系统监控、菜单栏或全局快捷键。请求排队执行，后续点击不会改写正在操作的文件选择。主窗口文件操作与 Finder 会话互不覆盖；剪切队列和密码在后台组件内存中保存，30 分钟无操作后清除并退出。可通过「设置加密密码」随时清除密码。

扩展使用 NSWorkspace 明确指定嵌入的 `iTools Finder Actions.app`，向它发送未全局注册的内部协议请求。它不是浏览器链接入口，不提供公开 URL handler；本机应用仍可以显式调用该组件，因此这不是对其他本机进程的身份认证。公开 `itools://finder` 继续只在主程序中展示待确认请求，保留外部链接的检查步骤。内部请求严格校验动作白名单、参数数量、路径、长度与请求编号；重复投递同一请求不重复执行。

## 0.4.1 历史修复：退出后唤起与移动安装位置

Finder 扩展由 macOS 单独运行，退出 iTools 主程序不等于停用扩展，因此菜单仍可显示。0.4.1 点击后在主程序展示待确认操作；这一交互已在 0.5.0 改为上面的直接执行。若希望移除菜单，请在系统扩展管理中停用 iTools Finder。

0.4.1 修复菜单回调依赖 representedObject 的问题：跨进程回传时该对象可能缺失，旧实现便直接返回。新版以 NSMenuItem.tag 对应扩展内部保存的请求，重建菜单不复用旧编号，保留有限的近期菜单供尚在传递中的点击使用；过期请求明确提示重新打开菜单。

扩展优先定位其所在的 iTools.app，再检查「应用程序」和系统登记位置；校验应用标识和可执行文件后，通过 NSWorkspace 明确指定主程序打开请求。移动、重命名或旧路径失效时不再只依赖通用 URL scheme 查询；启动失败会提示原因。主程序在界面初始化前收到的请求会等初始化完成后处理。

开发更新后应替换已安装的应用，而非同时打开多个开发副本；重新注册安装位置中的扩展，并让该扩展重新加载。用户已有历史和偏好位于独立的数据目录，不随替换应用包删除。

核对日期：2026-09-09。依据用户截图、项目 0.1.1 源码、当前 Mac 的扩展注册信息与官方功能说明。

## 压缩与扫描边界

- 7-Zip 26.03 从官方未修改的源码编译，Intel x86_64 / macOS 12.0，作为独立进程运行。完整对应源码、许可证和编译说明随应用分发。
- 每次压缩写入唯一临时目录，成功并通过完整性校验后才放到目标路径；不会覆盖已有压缩包。不允许输出位于原文件夹内部。
- 不同目录多选时，从共同父目录保留相对路径，避免重名覆盖。
- 通用 ZIP/7z 保存文件数据；不保证保存 macOS 资源分叉、扩展属性、自定义图标。适合文件传递，不替代系统备份。
- 压缩后移除原件使用废纸篓，便于恢复；与「彻底删除」是两个独立操作。快照用路径/设备/inode/大小/权限/纳秒修改时间与变更时间检查，不是文件系统快照。
- 扫描显示逻辑字节数，不是 APFS 独占物理空间；硬链接逐项计数。只读访问被拒绝的项目会累计错误，取消时明确标出部分结果；列表显示最大的 100 项。
- AirDrop、Finder 图标/替身等系统交互仍应在日常实机使用中验收；自动化未实际发送文件给第三方或删除用户资料。
