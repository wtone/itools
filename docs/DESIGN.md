# iTools 设计与架构

面向继续使用 Intel Mac 的用户：一处管理、按需运行、本机处理、低负担。最低部署 macOS 12，避免 SwiftUI NavigationSplitView、MenuBarExtra 等新版系统依赖。2026-10-07 验证环境为 Apple Silicon / macOS 15.8.1 / Xcode 16.4；通用版同时编译 x86_64 和 arm64，最低部署目标仍为 macOS 12。

## 界面

工作区使用中性浅灰 #F4F5F7 / 深灰 #202123，原生磨砂底层和低强度透明叠层；正文深浅自适应，交互使用系统风格蓝色，模块仅以少量彩色图标区分。使用 macOS 系统字体；页面标题 22、栏目 15、正文 12–13、辅助 10–11，读数使用等宽数字，卡片圆角 16。

布局：固定 218px 侧栏、紧凑品牌区域，保留系统原生窗口按钮与拖动标题区。右侧统一标题、留白和功能操作；⌘1–⌘7 切换页面，⌘, 打开设置。主页提供截图、剪贴板面板、文件与窗口入口，快捷键文案读取实际绑定。支持浅深色、最小窗口、减少透明度、原生焦点与系统对话框。

审视：这是一款常驻菜单栏的原生桌面工具，工作区不使用网页式 hero、渐变海报或营销统计。表达重点放在系统原生控件、清楚的可用状态和少量模块颜色。

## 模块边界

- IToolsCore：可测试的剪贴板模型、配额策略、文件操作、窗口几何、URL 工具、能力定义。
- ITools：SwiftUI 界面，AppKit 窗口/菜单栏，按需启动的各服务，统一错误报告。
- SystemBridge：Darwin 主机统计、网络接口计数、只读 AppleSMC，以及限定主屏菜单栏的本进程 AppKit 兼容入口。读取失败返回不可用，不伪造温度或风扇数据。
- FinderSync：独立沙盒 app extension，通过 `FinderLaunchEvent` 的 application-open 事件将严格解析的操作与路径传给同一应用包内的 Finder Actions 后台组件。扩展从自身所在位置推导组件路径，由 Launch Services 验证启动；不通过直接读取沙盒外的主程序或组件来判断是否安装。主程序的公共 `itools://finder` 仍仅导入待确认操作；`itools://finder-error` 只显示启动错误，不执行文件动作。

运行：剪贴板需用户开启后才监听；监控可关闭并释放计时器；录制仅显式启动；权限按操作请求。全局快捷键用 Carbon RegisterEventHotKey，无需捕捉全部键盘输入。截图、文本识别、标注与文件操作都在本地。

菜单栏绘制：工具箱 16 点、普通指标列 28 点、网速列 58 点，每个项目独立使用 macOS 原生的两侧 8 点留白，不添加额外自定义边距。上方数值使用 11 点半粗等宽数字，下方名称使用 7.5 点中等字重；网速两行都是数值，统一使用 10 点等宽数字并从同一左侧起点绘制，其他列居中。保留 22 点图像高度与系统模板图像，极长读数仅在固定列内缩放。设置页预览复用相同的图像和尺寸，避免两处布局不一致。

传感器：Intel 与 arm64 都尝试只读 AppleSMC；沿用键信息（9）及读字节（5），验证返回长度、状态和数据类型，不发送写命令。`sp78` / `fpe2` 与浮点值统一解码，非法或缺失数据保持不可用，合法的风扇 0 RPM 保留。Intel CPU 键保持原样；M2 仅读取已知 CPU 核心键，输出成功读取的最高值并传递来源标记，不以 GPU / 主板 / 电池温度替代 CPU。键地址参考 [Stats 的传感器清单](https://github.com/exelban/stats/blob/master/Modules/Sensors/values.swift)，解码与取值沿用本项目独立实现。当前 M2 Pro 已实测，其他芯片映射未因此视为已适配。沿用每 10 秒传感器采样，无特权辅助组件或风扇控制。

菜单栏主屏限制：显示器以 `NSScreen.screens.first` 为准，位置仍由 AppKit 状态项及 autosave 管理。只调透明度会保留副屏布局和命中区域，因此 `PrimaryStatusItem.m` 在公开创建流程上接入本进程的内部 metrics / replicants 回调，仅处理带有 iTools 标记的状态项，其余项目原样调用原实现。原始合成器项目限定到主显示器，副本执行原生卸载；窗口高度使用目标屏的原生菜单栏高度。保存的正常位置只用于恢复 AppKit 隐藏再安装时的 `FLT_MAX` 特殊值，不提供第二套可编辑位置状态。

内部入口是兼容性依赖：使用前检查方法签名、字段和对象类型、metrics 结构。入口签名不兼容时，多屏隐藏普通状态项，用户仍可从 Dock 或快捷键打开工具；单屏保留普通状态项。暂未准备好的 metrics 会等待后续刷新。按钮与弹框的屏幕坐标读取本应用窗口的 WindowServer 元数据，避免使用曾属于另一屏的 AppKit 缓存坐标。不改变 macOS 主屏或 Spaces 设置。实机范围和验证边界见 `VALIDATION.md`。

刘海位置保护使用主屏 `auxiliaryTopRightArea` 的横向范围；原生菜单栏窗口高度可能大于辅助区域高度，不以竖向包含判断刘海碰撞。启动修正非有限、负数或超出可用宽度的本应用 autosave 位置；缺失偏好的新菜单项在内容宽度确定后初始化到靠左的可见位置；已有有效偏好（包括 0）保持原样。原生 preferred position 是插入顺序，不等于精确 x，因此分次等待原生布局完成，再读取自身 WindowServer 窗口的完整横向范围；必要时最多 11 次有限插入检查，保留最靠左的可见候选。主图标沿用 iTools.metrics autosave 名称，各指标在名称后追加原始枚举值。位置与排序由 AppKit 原生 autosave 唯一管理，采样只更新同一按钮的图像和读数。新项目或被遮挡项目恢复时按既有原生位置顺序整体检查可见性；自动放置没有独立永久排序状态，⌘ 拖动立即接管。恢复整组时先统一卸载，设置各项原生插入点，再统一安装，避免中间布局把其他项目移到过期的屏幕坐标。关闭指标或正常退出前保留其原生 autosave 键（AppKit 移除项目会删除该键），重新创建后通过既有安装入口恢复真实槽位。运行中持续遮挡至少 0.8 秒后恢复靠左的可见位置；同时更新既有 autosave 与本进程缓存。使用既有主屏限制，不增加永久位置状态、权限或菜单栏开关。

扩展不是下载执行任意代码的插件系统。新增原生能力按 CapabilityCatalog 声明版本/权限/实现情况，并添加服务、界面、测试。0.12.3 起不再提供四款参考应用的连接或启动入口；内置能力独立实现，不重新分发它们的二进制或私有资源。
